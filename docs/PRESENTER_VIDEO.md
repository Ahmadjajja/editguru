# Frame presenter videos

Frame has an explicit **Create video** mode for a script or topic, one consistent presenter, a voice, style, captions, length and frame shape. The conversation executes the connected Higgsfield Shorts workflow. Frame owns the durable brief, approval, attempt ledger and resulting editable project. It does not hold Higgsfield credentials or implement a substitute generation model.

Open with `open_presenter_studio`. The returned MCP App opens the creation panel; its `editor_url` is the local fallback. The local page also supports `/frame?create=presenter`. Ordinary `/frame` and `open_editor` retain footage-first onboarding. Existing projects have a **Create video** button.

1. Save a brief with a stable `request_id`. Updates require the current creation version and are allowed only in `draft`. Attach requested character photos and voice samples to the same conversation.
2. **Plan video** reserves a handoff before sending it. The receiving chat acknowledges its receipt token, resolves `/shorts`, checks the engine and live schemas, and saves an estimate using `quote_presenter_video`. The quote contains the complete plan and confirmed reference media IDs. Opening, saving and planning do not authorize paid generation.
3. The user reviews that saved plan and chooses **Approve and generate**. Approval binds the exact quote ID and credit ceiling. The new continuation handoff uses a new receipt token. Higher total costs require a fresh quote and approval; previous quotes and failed attempts remain in the ledger.
4. Before each paid request, save a unique step with status `submitting` and its maximum credit allocation. Save the actual provider job ID immediately afterward. A job ID and allocation cannot change. Submitted, completed and uncertain attempts cannot be reset to resubmit. Total allocations include failed attempts and cannot exceed the approved ceiling. A lost submission response requires provider recovery rather than another paid request.
5. Save the generation sandbox directory, manifests and editable artifact IDs in `checkpoint`. Follow the actual Shorts composition and review workflow. Upload and confirm the final MP4 and editable composition ZIP using Higgsfield's supported tools.
6. Call `import_presenter_video` with that actual final media ID, fresh tool-returned HTTPS URL, SHA256 measured in the sandbox and honest review. Frame validates public network destinations with pinned TLS/DNS, bounds the transfer, checks digest, audio, duration and requested frame shape, and creates a deterministic result project. It does not require another user upload. Replaying a lost import response returns the same project and rechecks the source hash. An already imported local result can instead be bound with `complete_presenter_video`.

Creations persist separately under `jobs/presenter-creations`. Result MP4s use the normal Frame project store and ordinary editing/revision tools. A quote, submitted message or provider job is never displayed as a completed video. Standalone browsers without a chat host expose the exact saved request for copying into the same conversation. Ambiguous delivery is preserved and never automatically retried.

## Verification and remaining acceptance

`tests/test_presenter.py` covers actual HTTP MCP routing, concurrent handoffs, stale versions, receipt scope, explicit approval, credit ceilings, immutable attempts and job IDs, quote history, private-URL rejection, checksum failures, real MP4 import, lost-response recovery and normal timeline editing. The test downloader is mocked; the MP4 probe, hashes and editable project are real. `tests/test_presenter_studio.mjs` covers the form, quote approval, progress, exact result routing, absent-host fallback and ambiguous delivery. Existing editor/revision suites remain passing.

The agent-owned Chrome check verified form entry, saving, reload persistence and 390px layout without horizontal overflow. The installed desktop runtime's identity and served bundle were verified. No paid presenter video was generated for this feature test. Actual character/voice consistency, full live provider orchestration and creative quality remain unverified. The hosted R2/account-isolated port is separate work; this local implementation is not a hosted-release claim.
